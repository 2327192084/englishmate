## 五、环境注意（HANDOVER 有详述，这里只挑新的）

### 推送：这次又多踩了两次
M HANDOVER 五.1 已记录「会有整条 github.com:443 不通的时段」，**11-21 14:26–14:35 又遇到一次**，
新增两条判断线索（已写进 HANDOVER）：

1. **分清 TCP 与 TLS**：`/dev/tcp/<ip>/443` 全部 `TCP OK`，但 `curl https://` 全部 `000`
   → 端口通、TLS 被 RST，**换 IP 无意义**
2. **用 80 端口做对照**：同一 IP 的 `http://` 返回 **301** 正常，`https://` 返回 000
   → 确认是 TLS 层被掐。用 `curl -L` 跟随那个 301 跳回 https 反而可能拿到 200（握手时好时坏）

**策略**：隔几十秒探一次，一探到 200 立刻 push；不要一失败就改命令或换方案。
可用 IP 池会变：`140.82.112.4` / `.113.4` / `.114.4` / `.116.4` / `.121.4`（`.3` 系列基本不通）。

`ssh.github.com:443` 与 `github.com:22` 两次都通，但 `~/.ssh/` 没密钥 —— 配 SSH key 可绕开这个干扰。

### 其他地方照 HANDOVER 第五节做，重点是三条红线
1. 推送必须带 `-c credential.helper=` 先清空（`-c` 是**追加**不是替换）
2. 改源码只用 Edit/Write，禁 `sed -i`/`python -c`/超长 `node -e`
3. 桌面版只换 `resources/app/dist`，**绝不换 `main.cjs`/`preload.cjs`**（换 origin 会让用户学习进度不可见）
